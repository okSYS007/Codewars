# Codewars 6 kyu workspace instructions

Эта папка содержит отдельные Python-решения задач Codewars. Каждый файл обычно называется именем каты и включает условие в комментариях, затем одну или несколько функций решения.

## Рабочий процесс для агента

1. Когда появляется новый файл с условием задачи и сигнатурой функции, сначала определи имя основной функции и смысл задачи по условию.
2. Сохраняй условие задачи вверху файла. Не удаляй пользовательские комментарии без явной просьбы.
3. После реализации добавляй компактные локальные тесты в конец этого же файла в виде комментариев:

```python
# --- local tests ---
# test.function_name((arg1, arg2), expected)
# test.function_name((arg1,), expected)
```

Для функции с одним аргументом аргументы все равно записывай кортежем: `("abc",)`.

4. Создавай 5-10 тестов на задачу:
   - примеры из условия, если они есть;
   - маленькие базовые случаи;
   - граничные случаи;
   - 1-2 больших случая, если задача про производительность.
5. Не добавляй в kata-файлы импорты `codewars_test`, `pytest` или отдельные тестовые раннеры, если пользователь не попросил. Формат тестов нужен как короткая памятка рядом с решением.
6. После прохождения решения обязательно сделай короткий рефакторинг:
   - убери лишние ветки и повторения;
   - проверь асимптотику на ограничениях из условия;
   - сохрани читаемость, не превращай решение в code golf.
7. Если задача уже решена, перед изменениями проверь текущую реализацию и тесты, затем вноси минимально нужные правки.

## Git

Не делай автопуш изнутри решения задачи. Для автокоммита и push используй отдельный watcher-скрипт:

```powershell
.\scripts\watch-codewars-autopush.ps1
```

Watcher коммитит и отправляет измененные `.py` файлы в репозиторий после сохранения. Запускай его только когда действительно нужен автоматический push при изменениях.
